## Confirmed bugs and design decisions

1. Reserved faculty review policy allowed an assignment and request with matching
   blank IDs; malformed strings/dates could throw. The pure decision now checks
   non-empty identities and metadata and finite normalized Date values before
   comparison. Unknown shapes deny, rather than surfacing runtime exceptions.
   It deliberately does not coerce IDs or raw Firestore timestamps into authority.
   An adapter must normalize timestamps before a future route uses this policy.
   This is defense-in-depth preparation, NOT an exposed production faculty leak:
   there remains no faculty UI or clinical-review endpoint.
2. A stale queue unsubscribe called again after a same-scope replacement could
   delete the replacement registry entry, creating duplicate timers/listeners
   on the next subscription. Cleanup now releases only the group it owns, using
   identity comparison already used by the realtime coordinator. The alternative
   was another closed-state registry; ownership comparison is smaller and keeps
   resource lifetime encapsulated in the existing shared polling module.

Both new regressions failed against the original implementation; structured
observations are preserved in evidence/2026-11-22-retest/red-phase.json. Positive
assignment, wrong-reviewer/session, expiry, malformed fields/dates and invalid
clock cases are tested. Queue tests assert one timer/listener after repeated
stale cleanup and zero resources after final cleanup. Existing 100-consumer and
100-visibility-cycle budgets remain in the maintained suite.
